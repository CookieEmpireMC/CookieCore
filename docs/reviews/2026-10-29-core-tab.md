## 3. Bugs and findings
### MEDIUM
**M-1 `rank/RankSource.java:32`: a LuckPerms group with a prefix but no weight hides the chat.yml order.**
`orElse` takes the order from LuckPerms when `own > 0 || first.prefix(player).isPresent()`. A player whose LuckPerms group has a prefix and no weight gets order 0 and sits with the ordinary players. The same player with no LuckPerms prefix gets the chat.yml order and is listed first. On a server that sets prefixes without weights, staff are not listed first, which breaks "staff and ranks come first" (brief, player story). The test `RankSettingsTest.aLuckPermsGroupWithoutWeightDoesNotHideTheChatYmlOrder` pins the consistent rule and is `@Disabled` until the fix.
- **Fix (coder):** `return own > 0 ? own : other.order(player);` (drop the prefix check), then remove the `@Disabled` on that test.
- **Policy decision (Rick):** a LuckPerms weight of 0 means "no weight" (LuckPerms counts a group without weight as 0), so the chat.yml order applies. The alternative, LuckPerms order always wins while the plugin is present, would hide the chat.yml ranks for every user LuckPerms has not loaded yet. Not recommended.

### LOW (PR follow-ups, no fix round)
- **L-1** `tab/TabService.java:94`: join reads the list order from Paper (`BukkitTabSink.order(Player)`) and sets it only when it differs. One read per join, harmless. It is the only read back of Paper state; `docs/architecture.md` says so.
- **L-2** `tab.yml` `name-format`: a placeholder in the name that changes (`<ping>`, `<tps>`, `<online>`, a registered key) makes Paper send the name to every viewer of that player on each change. Say in the file that the name takes `<rank_prefix>` and `<player>`.
- **L-3** Double permission refresh at join with chat on: `chat/JoinListener.java:43` (`ranks.refresh`) and `tab/TabListener.java:25` (`ranks.join`). Keep one, the `Ranks.join` call.
- **L-4** `scoreboard/BuiltInPlaceholders.java:14` lists `player server online max ping` only. `tps` and `rank_prefix` are built-in for the tab list (`tab/CompiledTab.java:29`), so a plugin can register them for the sidebar, and the tab silently ignores that registration. Add both to the scoreboard built-ins, or document the overlap.
- **L-5** Test gap: `LuckPermsRankSource.order` weight clamp (`rank/LuckPermsRankSource.java`). The constructor needs the Bukkit service registry. Suggest a package-private constructor taking `LuckPerms`, so weight 0, an unknown group and a negative weight can be tested.

- **L-7** `tab/TabService.java:132` and `:158`: `List.copyOf(viewers.values())` allocates one list per second. Negligible.

## 4. The brief's checks on the coder diff
- **Correctness:** the diff logic matches the brief in every case the tests cover (section 2). Header and footer go as one packet, name and order as one packet each, and only when the rendered text changed.
- **Packet spam:** an unchanged tick sends nothing (test); a ping change resends header and footer only (test); a TPS change inside the shown digit sends nothing (test); reload and join resend once (test).
- **Main thread:** `TabService` runs on the main thread through `repeatOnMainThread` (scheduler only in `CookieCore`). `Bukkit.getTPS()` is called only from the task. `getPing()` only for shown players (`refresh` runs only for `viewers`).
- **Join timing:** name and order are set inside `PlayerJoinEvent` (normal priority), before the player-info packets, as the research note describes. The header and footer timing is UNVERIFIED in game (accepted).
- **Rank refactor (behaviour-preserving):** chat tests (`ChatSettingsTest`, `ChatListenerTest`, `JoinListenerTest`, `ChatCommandsTest`) pass unchanged except for the imports and the `rank()` accessor. `StaffChat` and `ChatListener` use the same `RankSource`. `RankSource.order` defaults to 0, so existing sources are unchanged. `net.luckperms` only in `rank/LuckPermsRankSource.java` (architecture test). `RankSources.create` checks `isPluginEnabled` and catches `LinkageError | RuntimeException`. Behaviour change, intended: the permission ranks are loaded and refreshed at enable and reload even with `chat.enabled: false`.
- **CoreWiring and order:** `Ranks` is built and reloaded before `TabModule`; `TabModule.loadConfig` and `apply()` follow; `CoreWiring` registers the tab listener and calls `apply()` after the sidebar and before the fly tracker and chat. Reload calls `ranks.reload` before `tab.apply()` and before `chat.apply()`. `tab.enabled` is stored before `tab.apply()`. `CookieCore.java` is 199 lines (cap 200).
- **Memory:** `TabService.quit` removes the viewer (also `Ranks.quit` through `TabListener`); a failed refresh drops it; a tick drops an offline viewer; `reconfigure` and `shutdown` clear the map. `PermissionRankSource` swaps its map whole on reload, so nothing from earlier logins stays. Nothing grows with logins.
- **Disable reset:** kept (orchestrator decision). It sends one reset per shown player at shutdown and when `tab.enabled` turns off. Documented in `docs/architecture.md`.
- **Phase 2 (scoreboard teams):** unverified, as the brief says. No code guards it. Check the doubled prefix when phase 2 adds teams with prefixes.
- **Accepted, not findings:** header and footer timing; the doubled team prefix; rank changes at rejoin or reload; clients older than 1.21.2 ignore the list order.

## 7. In-game guide (Paper 26.3; two accounts, one with a rank; LuckPerms optional)
Run after M-1 is fixed. Each step says what "good" looks like.
1. **Start:** no tab warning in the console. Problems in `tab.yml` are named by file.
2. **First join:** the header shows the server name and the subtitle, the footer shows Ping, TPS and Online x/y, and your name carries the chat.yml prefix on the first frame. No plain name flashes; if the header is blank for a moment, note the timing (UNVERIFIED).
3. **Order:** with a second account, the ranked account is listed above the others; ordinary players are alphabetical.
4. **Ping and TPS, 2 minutes:** the footer's ping changes now and then; no flicker; names never change.
5. **`tab.yml` edit plus `/cookiecore reload`:** the new header appears for everybody online. Break the file (bad YAML): reload names the line and keeps the old text. Fix it again: the new text appears.
6. **`tab.enabled: false` plus reload:** everybody online gets the vanilla list once, then nothing changes. Set it back to true plus reload: the tab returns.
7. **Restart with two players online:** both see the tab at once, with the right order.
8. **LuckPerms present:** set group weights (admin 100, member 10). The order follows the weights. A group with a prefix and no weight follows the chat.yml order after the M-1 fix.
9. **LuckPerms absent:** the order follows the chat.yml ranks only.
10. **Rank change:** change a player's group, then rejoin: the new prefix and order appear. Without a rejoin they stay (documented).
11. **`chat.enabled: false` (restart):** the tab still shows prefixes and order.
12. **Another plugin that sets list names or headers (if installed):** no fight loop; `/cookiecore reload` restores ours once.
13. **Clients:** on 1.21.2 or newer the order is shown; older clients show the names and header only.
14. **Profile with spark:** `/spark profiler start --timeout 60` with 20 or more players, some moving and clicking. Good: CookieCore's share of the tick is well under 0.1% when nothing changes, and rises only when TPS or a ping crosses a shown step.
15. **Phase 2 (later):** with a scoreboard team prefix on a player, the name is not doubled.
16. **Default texts:** the user checks `tab.yml` (brief, Needs human review).
